CONTEXTO
Continuação do Cedro Plus. O backend hoje usava um WebSocket handler antigo (removido),
endpoint antigo removido) para chat — a sinalização de chamada via Agora já foi removida.
O mobile já foi implementado esperando STOMP (@stomp/stompjs, endpoint /ws-chat), então
vamos migrar o BACKEND para STOMP e ajustar mobile e web pra falarem o mesmo protocolo.

=== PARTE 1 — BACKEND: migrar para STOMP ===

1. Adicionar no pom.xml (se ainda não houver): spring-boot-starter-websocket

2. Criar/substituir config/WebSocketConfig.java:
   - Implementar WebSocketMessageBrokerConfigurer, anotar com @EnableWebSocketMessageBroker
   - registerStompEndpoints: endpoint "/ws-chat", com HandshakeInterceptor customizado
     (ver item 3), sem SockJS (mobile RN e web moderno conectam STOMP nativo via WebSocket)
   - configureMessageBroker: enableSimpleBroker("/topic", "/queue"),
     setApplicationDestinationPrefixes("/app"), setUserDestinationPrefix("/user")

3. Criar security/StompHandshakeInterceptor.java (implements HandshakeInterceptor):
   - No beforeHandshake, extrair "token" da query string da URL de conexão
     (ex: /ws-chat?token=<jwt>)
   - Validar o token via JwtUtil (já existente)
   - Se inválido: retornar false (recusa o handshake)
   - Se válido: colocar userId extraído do token em attributes.put("userId", ...) pra
     ficar disponível na sessão STOMP

4. Criar security/StompPrincipalHandshakeHandler.java (extends DefaultHandshakeHandler):
   - Sobrescrever determineUser() retornando um Principal cujo getName() é o userId
     (string), lido de attributes.get("userId") do handshake
   - Registrar esse handshake handler no registerStompEndpoints junto com o interceptor

5. Criar controller/ChatStompController.java:
   - @MessageMapping("/chat.send") recebendo um DTO { destinatarioId, mensagem }
   - Extrai remetenteId do Principal da sessão (via parâmetro Principal principal no
     método), salva a mensagem via MensagemService (reaproveitar a lógica que já existe
     no MensagemController/Service)
   - Envia a mensagem salva via
     simpMessagingTemplate.convertAndSendToUser(destinatarioIdString, "/queue/mensagens", payload)
     tanto para o destinatário quanto de volta para o remetente (confirmação de envio)
   - @MessageMapping("/presence.ready") apenas loga/confirma conexão (pode ficar vazio
     ou enviar um ack simples)

6. (REMOVIDO) websocket handler antigo e qualquer registro antigo dele em
   WebSocketConfig

7. Garantir que não sobrou nenhum handling de call:offer/answer/ice/reject/end (deve já
   ter sido removido no sprint do Agora, mas confirmar)

=== PARTE 2 — MOBILE: ajustar chatService.ts ===

3. Remover qualquer WebSocket puro (new WebSocket(...)) que ainda exista relacionado a
