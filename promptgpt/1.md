CONTEXTO
Projeto Cedro Plus — backend Java Spring Boot 3.5.7 + SQL Server, frontend React + Vite.
Vamos substituir as chamadas de voz/vídeo via Agora.io por reuniões automáticas no Google Meet,
criadas via Google Calendar API, usando uma conta "sistema" fixa autenticada por refresh token
(a autorização OAuth já foi feita fora do projeto, o refresh token já existe).

Implemente exatamente as mudanças abaixo, mantendo os padrões já usados no projeto
(nomenclatura em português nas entidades/campos, estilo dos controllers/services existentes).

=== PARTE 1 — BACKEND (Google Meet + Calendar API) ===

1. Adicionar no pom.xml:
<dependency>
  <groupId>com.google.api-client</groupId>
  <artifactId>google-api-client</artifactId>
  <version>2.9.0</version>
</dependency>
<dependency>
  <groupId>com.google.apis</groupId>
  <artifactId>google-api-services-calendar</artifactId>
  <version>v3-rev20260225-2.0.0</version>
</dependency>

2. Novas variáveis de ambiente lidas via @Value em application.properties:
GOOGLE_CLIENT_ID
GOOGLE_CLIENT_SECRET
GOOGLE_REFRESH_TOKEN
GOOGLE_MEET_RELEASE_MINUTES_BEFORE=15   (default 15 se não setado)

3. Criar migration SQL idempotente em "SQL Cedro/google_meet_columns.sql", adicionando em `sessoes`
   (verificando antes se a coluna já existe):
   - link_reuniao VARCHAR(255) NULL
   - google_event_id VARCHAR(255) NULL

4. Atualizar a entity Sessao.java: adicionar campos linkReuniao (String) e googleEventId (String)
   mapeados pras colunas acima. Atualizar os DTOs de resposta de sessão relevantes pra incluir
   esses campos.

5. Criar GoogleMeetService (pacote service):
   - Construir credencial via com.google.auth.oauth2.UserCredentials.newBuilder()
     usando clientId, clientSecret, refreshToken das env vars
   - Construir o Calendar client (com.google.api.services.calendar.Calendar.Builder) usando
     a credencial via com.google.auth.http.HttpCredentialsAdapter como HttpRequestInitializer
   - Método criarReuniao(Sessao sessao, String nomePaciente, String nomePsicologo):
     - Cria Event com summary "Sessão Cedro Plus - {nomePaciente} & {nomePsicologo}"
     - start/end calculados a partir de sessao.getDataSessao() e sessao.getDuracao() (minutos),
       timezone America/Sao_Paulo
     - ConferenceData com createRequest: requestId = UUID.randomUUID().toString(),
       conferenceSolutionKey type "hangoutsMeet"
     - Insere no calendário "primary" via
       calendarService.events().insert("primary", event).setConferenceDataVersion(1).execute()
     - Retorna { link = event.getHangoutLink(), eventId = event.getId() }
     - Se falhar: logar erro (logger.error), NÃO lançar exceção pra cima — a sessão deve
       continuar sendo criada mesmo sem o link (linkReuniao/googleEventId ficam null,
       permitindo retry manual depois)
   - Método cancelarReuniao(String googleEventId): chama
     calendarService.events().delete("primary", googleEventId).execute(),
     ignorando erros 404/410 (evento já removido)

6. Alterar SessaoService:
   - No método que confirma pagamento (ex: confirmarPagamento), após mudar status pra "agendada",
     chamar googleMeetService.criarReuniao(...) e persistir linkReuniao/googleEventId na sessão
   - No cancelamento de sessão (status "cancelada"), se googleEventId != null, chamar
     googleMeetService.cancelarReuniao(googleEventId)

7. Novo endpoint em SessaoController:
   GET /api/sessoes/{id}/link-reuniao (JWT obrigatório)
   - Verifica que o usuário autenticado é o paciente, o psicólogo dono da sessão, ou admin
     (senão 403)
   - Calcula se now >= (dataSessao - GOOGLE_MEET_RELEASE_MINUTES_BEFORE minutos)
   - Se ainda não chegou a janela: 200 com { liberado: false, disponivelEm: <ISO datetime> }
   - Se já pode: 200 com { liberado: true, link: sessao.getLinkReuniao() }
   - Se não tiver link gerado (falha anterior): { liberado: true, link: null,
     erro: "Link ainda não gerado, contate o suporte" }

8. Endpoint auxiliar: POST /api/sessoes/{id}/gerar-reuniao (JWT admin) pra forçar retry manual
   de geração do link, caso a criação automática tenha falhado.
